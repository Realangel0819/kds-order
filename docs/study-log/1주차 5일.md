
## 오늘 목표
- **오늘 무엇을 이해해야 하는가?** gRPC가 무엇이며, 왜 기존의 REST API 대신 마이크로서비스 간 통신(Service-to-Service Communication)에 사용되는지 내부 원리를 이해한다.
    
- **왜 배우는가?** `order-service`가 `menu-service`의 메뉴 정보를 실시간으로 물어봐야 할 때, 둘 사이의 통신이 느리거나 무거우면 전체 주문 시스템이 마비된다. MSA 환경에서 고성능 통신을 구축하기 위함이다.
    
- **오늘이 끝났을 때 설명할 수 있어야 하는 것:** "HTTP/1.1 기반의 REST API와 HTTP/2 + Protobuf 기반의 gRPC의 결정적 차이는 무엇인가?"

  

## 배운 개념 (내 언어로 설명)
- gRPC란 Google이 개발한, **HTTP/2를 기반으로 동작하며 바이너리 포맷을 사용하여 초고속으로 통신하는 RPC(Remote Procedure Call) 프레임워크**
- rest를 안쓰는이유는 서버와 서버 마이크로서비스끼리 통신할때에는 json으로 하면 쓸데없이 용량이크고 http/1.1통신은 헤더도 크고 요청 대기로 쓸데없는 시간이많음, 문서를 보고 dto를 매핑해야하고 서버간 스펙 불일치 문제가 많이 발생한다. // 그냥 내부통신지연이큼
- Protocol Buffers : gRPC 에서 사용할 데이터 구조와 서비스인터페이스를 정의하는 언어 독립적인 계약서
